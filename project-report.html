1. Executive Summary

This project implements an AI-powered Digital KYC (Know Your Customer) Onboarding and Identity Threat Mitigation System for Indian Overseas Bank. The system automates the entire customer onboarding pipeline — from document upload and OCR extraction, through multi-modal biometric verification (face matching, liveness detection, deepfake detection), to QR code verification and risk scoring.

Key Capabilities

  • Document OCR: Aadhaar & PAN card text extraction with field validation
  • Face Verification: ArcFace embeddings with 55% similarity threshold
  • Liveness Detection: 8 random challenges (turn head, raise hand, blink, nod, etc.) with pose landmark tracking
  • Deepfake Detection: 2-model ensemble — Xception (55%) + F3Net (45%) with 0.65 threshold
  • QR Verification: Aadhaar/PAN QR code field-by-field comparison (Name, DOB, ID Number, PAN)
  • Risk Scoring: Multi-factor risk assessment (face match, liveness, deepfake, QR, duplicate detection)
  • Re-KYC: Existing customers can update KYC with diff comparison
  • RBAC: User / Employee / Admin role-based access control

2. System Architecture

The system follows a 3-tier architecture with a microservice AI backend, a Spring Boot REST API, and a static HTML/JS frontend.

Figure 2.1 — High-Level System Architecture

Architecture Principles

  • Separation of Concerns: AI/ML logic fully isolated in Python Flask microservice; Java handles business logic, auth, and data persistence
  • Stateless API: JWT-based authentication with no server-side sessions
  • Lazy Loading: spring.jpa.open-in-view=false with EntityGraph for controlled fetching
  • DTO Pattern: Lightweight DTOs for list endpoints to exclude large base64 blob data
  • Defense in Depth: 3-gate verification — Face Match + Liveness + Deepfake must ALL pass

6.2 Liveness Detection — 8 Challenge Types

Each session randomly picks 3 challenges. The user must complete all 3 correctly using real-time pose tracking. Anti-spoofing features: printed photo detection, screen replay detection, pre-recorded video detection.
#ChallengeLandmarks UsedVerification Method
1Turn Head Left/RightNose, ShouldersHorizontal displacement threshold
2Raise HandWrist vs Shoulder Y-positionWrist above shoulder line
3Blink EyesEye landmarks (EAR ratio)EAR_CLOSED_THRESHOLD = 0.16
4Nod HeadNose Y-coordinate changeVertical displacement threshold
5SmileMouth cornersMouth width increase
6Open MouthUpper/Lower lipLip distance threshold
7Look Up/DownNose Y-coordinateVertical nose displacement
8Neutral PoseAll landmarksStable pose for 2 seconds

6.3 Three-Gate Verification Logic

verified = gate1_pass AND gate2_pass AND gate3_pass gate1_pass = (face_similarity >= 0.55) // ArcFace threshold gate2_pass = (liveness_score >= 3) // At least 3 of 3 challenges passed gate3_pass = (deepfake_score <= 0.65) // Combined ensemble ≤ 0.65 // Deepfake ensemble: ensemble_score = 0.55 * xception_score + 0.45 * f3net_score // All models NEVER return null — 3-layer fallback: // 1. Try model inference // 2. Try alternative model // 3. Return 0.5/0.5 neutral (guaranteed non-null)

7. Security Architecture

Figure 7.1 — Security Layers

7.1 Security Configuration

  • CSRF: Disabled (REST API, stateless)
  • CORS: Enabled for frontend origin
  • Session: Stateless (no server-side sessions)
  • Password Encoding: BCrypt
  • JWT: Custom filter before Spring Security filter chain
  • Rate Limiting: 5 failed attempts → 15-minute account lockout
  • open-in-view: Disabled (prevents lazy loading leaks)
  • PII Logging: Suppressed — only metadata logged

10. Deployment Architecture

Figure 10.1 — Railway Cloud Deployment

10.1 Deployment Steps

  1. Code Push: git push origin main triggers Railway auto-deploy
  2. Java Build: Maven builds JAR, Railway deploys as web service on port 8080
  3. Python Build: pip install requirements, Flask starts on port 5001
  4. Database: Railway managed PostgreSQL, auto-provisioned
  5. SSL: Automatic HTTPS via Railway's built-in TLS termination
